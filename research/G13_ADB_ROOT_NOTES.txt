USAGE

From the connected laptop:
  adb -s 18ACC22D1C47 root
  adb -s 18ACC22D1C47 shell

For a single root command:
  adb -s 18ACC22D1C47 shell id

The modification is stored in init_boot_a. Request adb root again after a
restart if ADB has returned to the shell user. An update replacing this
image or a switch to an unmodified slot can remove the capability. There
is no su executable or Magisk manager installed by this change; apps do
not gain an su interface. adb unroot is the standard way to return adbd to
its ordinary shell identity without restoring the firmware image.

MECHANISM

The stock generic init contains /force_debuggable, /adb_debug.prop,
INIT_FORCE_DEBUGGABLE, /debug_ramdisk/adb_debug.prop and the userdebug CIL
paths. Android 14 first_stage_init.cpp copies the optional debug files into
the debug ramdisk, and selinux.cpp selects its platform policy when the
device is unlocked. property_service.cpp loads the debug properties last.

The live adbd APEX init service runs its binary with
--root_seclabel=u:r:su:s0 and user root. Its normal privilege drop depends on
ro.secure, debuggability and service.adb.root. Stock platform policy contains
the su type but lacks adbd's dynamic transition into it. The candidate adds:
  (allow adbd self (process (setcurrent)))
  (allow adbd su (process (dyntransition)))
  (typepermissive su)

This deliberately makes only the root shell's su domain permissive. Other
Android domains remain enforcing; this is not a globally permissive policy.
The debug properties are only:
  ro.debuggable=1
  ro.force.debuggable=1
ADB key authentication stays enabled (stock ro.adb.secure=1). The image does
not set ro.secure=0, automatically request root, or install a su executable.
The intended interface is adb root, followed by adb shell as uid0.

Only three files are added to a copy of stock init_boot_a's ramdisk:
  force_debuggable
  adb_debug.prop
  userdebug_plat_sepolicy.cil
All 22 existing entries, their order, metadata and bytes are preserved,
including the original TCL init. Kernel, vendor_boot, vbmeta, other slots
and userdata are not flashed. The unlocked state remains required.
