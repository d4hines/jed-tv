Driver and native-startup findings
----------------------------------
Every one of the 27 modules in the saved V013 /proc/modules inventory has an
ARM ELF counterpart labelled 5.15.180 in V033, including Mali, framebuffer,
MI/MTAL, Realtek Wi-Fi/Bluetooth and USB. vendor_dlkm contains 39 modules:
33 ARM and six AArch64 modules for other connectivity hardware. Seven ARM
modules append -gc43214a576b3 to their release string. Do not select modules
only by a loose filename/version match or load the AArch64 alternatives.
Symbol CRC compatibility and hardware operation have not been tested here.

V033 also requests tcl_dybridge.ko from init.fusion.rc, but that file was not
found in the extracted filesystem set. Do not describe this package as having
every referenced optional module merely because the existing 27 are present.

V033's stock init is byte-identical to V013:
  18b79298c5d1868d7b5b3bf77f69b664dc824b0120e47b0d663616d3febce75a
The generic ramdisk still has 22 original entries. Its platform CIL is also
byte-identical to the captured V013 policy. Stock policy and the existing
adb-root/native-startup additions compile with V033's matching vendor,
system_ext, product and mapping files. Debug variants intentionally use -N,
as the current owner-debug policy does; normal domains remain enforcing in
that design. Compilation is not a boot test or proof of policy correctness.

V033 audioserver differs from V013. Rebuild its standalone shimmed copy before
native startup; do not transplant the previously patched V013 executable.

Mandatory second update stage and remaining work
------------------------------------------------
The manifest enables virtual A/B, LZ4 compressed COW snapshots, COW version 2.
Only vendor has a postinstall action, and it is required:
  bin/AB_OTA_POSTINSTALL_fusion

That script writes its 50 MiB upgrade.img to the shared upgrade partition,
then calls trigOAD_fusion. The ext4 image contains upgrade_image_ota.pkg
(10948656 bytes). Its package header identifies an REE region; the encoded
payload has not been decoded/authenticated as a standalone service package.
It must not be advertised as independent USB recovery or a verified rollback.

The helper's real ARM main was executed for source slots _a and _b with
in-memory libc/property/environment mocks:
  nix develop .#bootloader -c python3 research/g13-v033/check-postinstall.py \
    assets/research/g13-v033-offline-20261101/extracted/vendor \
    assets/research/g13-v033-offline-20261101/postinstall-emulation.json

It selects the opposite slot's ota_oad mode, sets OAD_PARTITION=upgrade,
OadUpgradeFile=upgrade_image_ota.pkg and OadUpgradeStatus=start, and saves the
boot environment. Although set_env contains devicestate/adb_enable/first_setup,
the helper deliberately ignores those three names in both tested paths.
Other settings, including bootargs, are changed. The low-level storage writes,
MBOOT's second-stage package execution and failure recovery are not emulated.

Therefore this is more than a kernel replacement or an isolated inactive-slot
write. Before a physical trial, with renewed TV access, capture current boot
state and backups including MPOOL, upgrade and the modified boot images; check
snapshot state and USB/UART recovery; retain the required vendor postinstall.
Plan any native/root migration using V033 files and do not relax the Lean
loader's exact V013 checks without a reviewed V033 hardware profile.

The remaining decisive tests are physical V033 startup, recovery, root access,
display/audio/IR/network, native launch and standby/wake. The owner has not yet
authorized resuming TV access after the offline-only instruction.
