======================================
This inventory below records the planning basis; the moves are now implemented.
All runtime sources are under src/. Host groups are under tools/. Root ./flash.sh,
./repl.sh, ./hello.sh and ./shell.sh remain entry points. No TV action or build
was performed by the migration agent. New src/audio/bridge.rs remains untested
work-in-progress, not a completed/deployed audio feature.

Cargo and tools strategy
------------------------
Keep src/Cargo.toml as the app workspace. Add explicit excludes for moved
independent workspaces (pid1, launcher, legacy-doom, probes, experiments), or
add [workspace] to independent package roots. Do not absorb their lockfiles
and profiles into the app workspace accidentally. Use explicit cargo
--manifest-path and --target-dir in host tools so relocating .cargo config
cannot scatter outputs into src/assets. Keep compiler target specifications
next to the package that uses them.

A minimal migration need not invent a new top-level directory: use existing
src/, tools/, test/, research/, assets/. Thin root scripts (repl.sh, flash.sh,
hello.sh, shell.sh) may remain user entry points because they run on the host.
Do not turn old source paths into duplicate copies. Host compatibility wrappers
can refer to one canonical source location until callers are updated.

5. Compare semantic artifacts or document changed build identities. Do not
