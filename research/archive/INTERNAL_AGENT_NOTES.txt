Source layout rule agreed with the team: `src/` is the human-auditable source
that runs on the TV. Build-only tools, code generators, host-only checks and
other development machinery belong outside `src/` (for example `tools/`,
`test/`, or `nix/`). Keep TV runtime scripts in `src/`; do not place build or
code-generation scripts there merely because they build a particular app.

Lean source packages must set buildDir under assets/build/lake/. Generated
C, object files and binaries stay outside src/; .lake in src/ may contain only
Lake configuration metadata. Host tools must honor package buildDir overrides.

Shared main is collaborative: never force-push main or rewrite its published
history. Integrate concurrent work with normal merges and normal pushes.

Hackathon implementation rule: prefer one clear current implementation. Do not
add feature flags, backend selectors, compatibility branches, or fallback paths
just to preserve old behavior. Experiment on work branches; once a replacement
works, remove the superseded code and write the result as if it were the original
design. Reviewability matters more than backward compatibility. Keep necessary
hardware identity checks and resource-ownership checks.

Layout rule (owner, 2026-11-01): `src/` holds only what runs on the TV, plus
the Lean that TV code is generated from (the assembly DSL, the C ABI
descriptions) and proofs or specifications kept next to the code they are
about. Everything else lives outside `src/`: tests and checks in `test/`, host
tools and build scripts in `tools/`, Nix code in `nix/` (the flake stays at
the root), finished experiments in `research/`. A Lean package with both kinds
of code is split into the TV package in `src/` and a host package outside it
that requires it by path (e.g. `tools/lean/zr`, `test/lean/yt`, `test/doomtv`,
`test/slides`). Exception: a Rust crate's manifest, `build.rs` and in-crate
tests stay with the crate, where cargo needs them.
