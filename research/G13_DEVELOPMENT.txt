The G13 rtl8733bu driver rejected the original G06 WEXT association method.
Use its matching /vendor/bin/hw/wpa_supplicant with nl80211. It drops to
Android's wifi UID (1010), so the saved root-only PSK configuration under
/metadata/dande-tv/wifi/wpa.conf is copied to a private wifi-owned runtime
directory. Neither the password nor derived PSK belongs in Git or logs.
The static wpa_cli uses an explicit local socket directory; Android has no
/tmp. Its reply socket must be writable by UID 1010 inside that private
directory. Select network 0 explicitly after the vendor control socket is
ready. The G06 supplicant binary itself is not used on the G13.

native-g13.rc imports the optional /metadata/dande-tv/wifi/service.rc.
It starts dande-wifi when Ethernet/netd setup reports ready. The source is
src/runtime-scripts/network/{wifi-g13.rc,wifi-g13.sh,lease-g13.sh}; installed
paths are wifi/service.rc, wifi/start.sh under /metadata/dande-tv, and
/data/local/tmp/dande-g13/wifi/lease.sh. A private static BusyBox runs DHCP
and renews the lease; the hook writes app DNS to the chroot's resolv.conf.
Wi-Fi has its own bounded startup and cannot select Android fallback or
block Home. A missing optional service.rc on an unconfigured TV is ignored
by init. sys.dande.wifi_ready=1 means DHCP configuration completed.

UART
----
Current owner: the user's Screen session 96550, window 0, on ttyUSB1.
Use that session; never open a competing serial reader:

  nix shell nixpkgs#screen -c screen -x 96550

When no session owns the adapter, create one using its stable identity:

  nix shell nixpkgs#screen -c screen -h 10000 -fn /dev/serial/by-id/usb-FTDI_DCSD_USB_UART_AU0563JT-if00-port0 115200

Use 115200 8N1 with flow control off. Scrollback: Ctrl+A, then [, then
arrows/PageUp/PageDown; Esc returns to the live terminal. Ctrl+A then D
detaches. No sudo is needed with serial-device group access. A root-owned
old Screen session may require sudo to attach; session ownership and device
permissions are separate. The UART Android shell is uid2000, not root.

Persistent TV configuration
---------------------------
src/runtime-scripts/native-app/network-g13.sh is installed as
/metadata/dande-tv/network.sh. native-g13.rc starts it independently of
the launcher during post-fs-data. The script checks the exact TV/build,
waits for eth0 and netd's initial routing-rule flush, sets eth0 to .3/24,
adds the connected main-table route and priority-9000 subnet rule, and
enables authenticated ADB on port 5555. sys.dande.network_ready becomes 1
only after these commands succeed. It configures no Internet default route.

Two reproduced G13 differences required explicit handling:
  * netd flushes non-local policy rules during startup. Installing ours
    before that flush left the address present but Ethernet unreachable.
    The script waits for netd's terminal priority-32000 unreachable rule.
  * Root adbd's TCP accept passed a su-owned descriptor to enforcing netd,
    which denied its use and stalled the connection. Native init exports
    ANDROID_NO_USE_FWMARK_CLIENT=1. The exact libnetd_client supports this
    root-only bypass; the dedicated subnet rule supplies routing instead.
    This export applies to native G13 services, not the G06 or stock Android
    fallback. SELinux remains globally Enforcing and ro.adb.secure remains 1.

The ordering agrees with AOSP RouteController::Init (flushRules before
addUnreachableRule):
https://android.googlesource.com/platform/system/netd/+/master/server/RouteController.cpp
Root-only fwmark bypass reference:
https://android.googlesource.com/platform/system/netd/+/refs/tags/android-13.0.0_r42/client/FwmarkClient.cpp

To update just the network config from a working rooted ADB connection:

  nix develop -c python3 tools/native-app/g13-boot.py network

This verifies the installed image and existing manifest, saves the current
configuration under assets/research/g13-network-config-TIMESTAMP/, updates
network.sh/native.rc and their manifest hashes, preserves boot selection,
and applies network.sh immediately. Init rc/environment changes take effect
on the next normal boot. No flash is involved. Keep /metadata/dande-tv:
the installed startup image depends on its entry.rc. For Android fallback
and full recovery, read G13_NATIVE_BOOT_NOTES.txt and RECOVERY_NOTES.txt.
The static-IP service belongs to native startup; stock Android fallback
does not import it. A manual netd restart requires reapplying network.sh.

Fastboot is separate from ADB. The general Fastboot protocol defines
TCP/UDP transport on 5554, but this G13 has only a verified USB Fastboot
path, and its captured MBOOT startup reports "No ethernet found". Do not
assume adb over Ethernet provides network flashing. Keep UART and the
known USB Fastboot cable available for recovery.
https://android.googlesource.com/platform/system/core/+/master/fastboot/README.md

MBOOT separately reports kernel handoff around 2.51 s on its own clock;

different origin from Linux uptime; do not subtract them interchangeably.

The retained early kernel trace confirms the largest single identified
cost: init compiles /debug_ramdisk/userdebug_plat_sepolicy.cil on every

Policy loading then brings
second-stage init to about 6.02 s. This is a consequence of our debug/root
policy path: AOSP OpenSplitPolicy explicitly skips the vendor precompiled
policy when a userdebug policy is selected. The remaining startup includes
stock init/APEX/mount setup and vendor driver/media initialization. There
is no evidence here of a fixed 30-second sleep in our startup scripts;
their loops exit as soon as the required conditions hold.

The local improvement overlaps the sequential ctl.stop requests for unused
framework services with launcher setup. It prepares Home earlier, while
preserving the same services and display/audio readiness checks. Final
readiness changed by only 0.29 s in the first pair and returned to 18.66 s
on repeat: no meaningful total speedup is established. The media services
are now the later dependency. Next targets are loading an equivalent
precompiled debug policy and reducing/properly overlapping vendor media
startup. The former requires work before early-init; placing a cached file
in /metadata alone does not change stock init's policy-loading behavior.
Neither optimization is implemented by these script changes.

Parallel startup follow-up (2026-11-01)
--------------------------------------
Audio initialization now starts immediately after launching tvinit, before
waiting for the frame file. It does not consume that file or the private
chroot device nodes. This allows audio's library/service initialization to
overlap the launcher's namespace and first-frame preparation. Display and
OSD still start only once the frame file exists, and the supervisor retains
the same child cleanup and final display/audio readiness conditions.
Source: src/runtime-scripts/native-app/supervise-android.sh. This script is
specific to the G13 runner; no G06 scripts, app ABI or confinement changed.

The measured reboot reached Home preparation at 14.70 s, display readiness
at 18.61 s, audio readiness at 18.71 s, and READY at 18.80 s (Linux uptime).
Compared with the preceding 18.38/18.66 s runs, this establishes successful
parallel startup, not a total speedup. Logcat shows the native audio client
waiting for media.audio_policy at 13.562 s and returning at 18.571 s after
5009 ms. The earlier start is still gated by Android/vendor audio readiness.

Dependencies retained:
  * SELinux policy must be compiled/loaded before normal services start in
    their correct domains. Launching those services alongside compilation
    is not a safe scheduling change. An equivalent precompiled policy is
    the larger remaining opportunity; it is not implemented here.
  * Ethernet, native launcher preparation, audio and display already run
    concurrently once their prerequisites are met. The display needs both
    a valid frame and SurfaceFlinger/vendor compositor readiness.
  * Vendor startup has real ordering requirements. mtk_rm.sh waits for
    mknod_util_end; dtv_svc.sh waits for mtk_rm_end and /dev/fusion0 before
    launching the TV middleware. Several HALs in turn wait for dtv_svc.
    Their launch order was inspected but not modified speculatively.

For an existing verified G13 installation:
  nix develop -c python3 tools/native-app/g13-boot.py parallel
This updates only supervise.sh and its manifest entry after backing up,
syntax checking and verifying hashes. The running supervisor retains its
old open script; the new ordering applies on its next start. New builds and
the G13 manual runner also copy the updated source. No flash or reboot is
performed by this installer, and mode/entry.rc selection is preserved.
