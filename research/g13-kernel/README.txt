Build inputs
------------

prepare.py verifies the pinned archive and relocates the publisher's
/home/ubuntu/ack links into the extracted source tree. The missing
mstar3party directory is not referenced by this tree's Kconfig/Makefiles.
No placeholder driver sources are added.

build.py seeds its output configuration from the saved G13 /proc/config.gz
extraction, assets/research/g13-kernel-source-20261101/live.config, SHA256
90fcf9a9d0bc5d51da327392413b13fbd5ef3dcc4509346c67f2e00d361989aa.
It runs olddefconfig and builds Image, modules and dtbs. All 147 enabled
MSTAR_/MP_/MS_ settings are preserved, including MT5867. The 2.5 GiB virtual
split and physical RAM base match the G13 configuration.

The initial dubai_defconfig compile was stopped after discovering its
different 3 GiB split. It is retained as build-01.log and
dubai-config-resolved, not presented as the G13 build.

Nix supplies Clang/LLD 21.1.8; HOSTCC=cc and HOSTCXX=c++ use the wrapped
host toolchain with its C library headers. TCL used Android Clang 16.0.2.
NCT5_BUILD=true skips the vendor genlink.sh invocation in the output
directory; prepare.py has already supplied the correct source links.
makefile-boot.patch computes this board's kernel load address, 0x20208000,
using POSIX shell arithmetic instead of hard-coded /bin/bash (absent on
NixOS). It does not change the compiled kernel code.
KERNEL_VER=linux-5.15_14 selects the vendor's Android 14 build path, which
uses drivers/iommu/mtk_iommu_dtv instead of also compiling the legacy
mstar2/drv/mma implementation. MTK_IOMMU_DTV and MP_MMA_ENABLE stay enabled.
The .scmversion metadata labels the result with the pinned kernel commit
instead of accidentally inheriting the enclosing app repository's Git ID.

sync-debug.patch repairs an inverted CONFIG_DEBUG_FS guard in the release:
the timeline/list definitions must exist with debugfs enabled, and only
the debugfs-specific section is conditional. The original code fails to
compile with G13's SW_SYNC=y and DEBUG_FS=y. Both features stay enabled;
the QEMU smoke test reads /sys/kernel/debug/sync/info.

fixdep.patch aligns CONFIG dependencies with this tree's Kconfig generator:
Kconfig creates include/config/PAGE_OFFSET, whereas the unpatched fixdep
looked for include/config/page/offset.h. The mismatch silently retained a
3 GiB linker script after switching configurations and caused the first
QEMU attempt to abort before the console. A clean build is required when
adopting this patch over existing objects. check-fixdep.py verifies that
make actually rebuilds a dependent object when a CONFIG stamp changes.
build.py also checks stext against the selected PAGE_OFFSET plus 0x8000.
The superseded objects are retained in out-before-fixdep/ and the first
attempt in qemu-20261101T212848/ for diagnosis.

Some newer TCL/Android features do not exist in the 5.15.148 source, such
as the captured VMAP/dynamic-stack options, MTK_KO_COMP_PATCH and MTK_AND.
olddefconfig drops those options. Full differences are saved in build.json
and g13-config-audit.json. This is not an exact rebuild of TCL firmware;
TCL binary-module ABI compatibility remains unverified.

Emulation
---------

run.py uses the existing partial MT5867/G06 QEMU machine with four Cortex-A55
cores in AArch32, its UART/GIC/timer model, and the saved G13 live device tree.
The model's RAM covers the addresses in the G13 boot arguments; the G13
memory limits are passed to Linux. This does not add G13 peripheral models.

The kernel is loaded unchanged at 0x20208000; a 24-byte ARM entry stub sets
the standard boot registers. The G13 FDT is at 0x23000000 and a generated
BusyBox initramfs at 0x24000000. The BusyBox and libc are the hash-checked
Debian ARM userland inputs already used by tools/bootloader/qemu.py.
The kernel itself is built from the pinned MT5867 source.

Only the FDT's chosen command line and initramfs bounds are changed.
The initial initcall exclusions match the existing G06 emulator:
  mstar_mci_init          no eMMC model
  mmc_sdio_init           no SDIO model
  mtktv_regulator_init    no external PMIC/I2C model
  mtktv_thermal_init      no sensor/calibration model
  ir_dynamic_config_init no vendor runtime key configuration

An additional exclusion, mtk_wifi_ctl_init, is required with the saved G13
FDT: its wifi-ctl-gpio=65535 reaches MHal_GPIO_Set_Low out of bounds and
panics. This is a reproduced source/FDT compatibility problem, not proof of
working Wi-Fi. The kernel is unchanged for this exclusion; only the QEMU
command line changes. Evidence: qemu-20261101T213204/serial.log.

The G13 configuration disables devtmpfs. Our small initramfs therefore
supplies /dev/console and creates /dev/null and /dev/zero itself, instead
of depending on Android's device manager. The first userspace attempt's
devtmpfs mount failure is retained in qemu-20261101T213218/serial.log.

The initramfs checks PID 1, the built release, four online processors,
sleep/wakeup, child shell execution and a tmpfs read/write. Each run saves
the exact Image/config/FDT/initramfs, command, serial log, final registers,
and result.json. A successful init marker is required for PASS.

Most RIU registers are backing cells, with selected timer/cache-flush
behavior. Device registration messages do not prove working peripherals.
Display, audio, storage, networking, proprietary modules and physical
boot/recovery behavior require separate validation.

The successful boot still reports unavailable OP-TEE/IOMMU sessions and
bounded MMC timeouts before starting init. These are expected limitations
of this model, not successful device probes. The unmodified vendor code
also emits six modpost section-lifetime warnings involving chip_early_vprintk,
mstar_rtc_probe, mstar_fb_probe, mtk_pwm_probe, MDrv_SYS_SetGraphicAddr and
MDrv_SYS_SetGraphicMirror. They remain to be reviewed before hardware use.
