HARDWARE-DRIVEN ABI CORRECTION (2026-11-01T01:33Z)
The native G06 trial successfully loaded mik with the configuration pack,
but a direct SYS GET ioctl returned vendor code 8 and the kernel interpreted
the requested status selector as the attribute number. Inspection then
found libmi3 ioctl_wrapper at 0x5090c adds a REQUIRED outer envelope to every
non-null ioctl argument: {u16 _IOC_SIZE(request), zero[6], u64 argument_ptr}.
Thus SYS needs THREE levels: outer wrapper -> {u64 attr,u64 status_ptr}
-> 8-byte status. DISP/OSD 12-byte structs also require that outer wrapper.
The earlier direct-syscall interpretation below was incomplete; the updated
mi-display-abi.h includes the outer type. check-ioctl-wrapper.py emulates the
exact V109 wrapper instructions with Unicorn, stops at the ioctl PLT call,
and checks actual fd/request/16-byte outer wire for all four commands.
All four passed; evidence: assets/research/g06-display-offline/
ioctl-wrapper-check.json. This does not establish successful MI calls on TV.
Native devtmpfs exposes /dev/mik/sys; Android uses /dev/mik!sys.

RESULT
There is an actionable smaller path than running the stock glibc midaemon:
provide the exact configuration hierarchy BEFORE module loading, enable the
existing in-kernel DISP/OSD init branches, then use a native helper to verify
real initialization and publish readiness before opening fb0. This is an
OFFLINE-derived candidate, not a demonstrated successful load/display or a
proof of the runtime-minimal file set. No TV access or reboot occurred.

The owner's concurrent hardware report establishes the immediate failure:
missing mik_init.ini and sys.ini made MI initialization abort. That report was
not independently measured by this offline work. The owner also reports that
Ethernet program replacement and kernel-log return worked on hardware.

3. REAL INITIALIZATION CALLS AND ABI
The smallest candidate uses existing kernel init to avoid glibc/midaemon:
  init_module -> MI_DEV_SYS_Init -> MI_SYS_Init
              -> MI_DEV_SYS_ModuleInit -> MI_DISP_Init(&disp)
                                       -> MI_OSD_Init(&osd)
After enabling the two INI flags, exact calls are:
  .text+0x34674 MI_DISP_Init
    struct: u32 output_timing at +0, u32 tv_system +4, u32 de_flicker +8
    exact stock INI values: {6,6,0}; this is not framebuffer geometry
    success -> MI_SYS_SetAttr(5,{u32 selector=6,u8 ready=1,pad[3]}) at +0x34698
  .text+0x34a80 MI_OSD_Init
    12-byte struct: u8 wait_sync +0, u8 auto_flip +1, padding +2..3,
    u32 canvas_mode +4, u16 surface_count +8, u8 wait_idle +10, pad +11
    exact stock INI values all zero (surface_count 0 means default 64)
    success -> MI_SYS_SetAttr(5,{selector=9,ready=1}) at +0x34aa4
Both nonzero return branches abort module initialization. Preserve their
actual return values/logs rather than treating a created node as success.
MI_DISP_Init -> _MI_DISP_XC_Init -> MI_DISP_IMPL_XC_Init_EX, etc.
MI_OSD_Init -> mi_osd_InitHW -> MApi_GFX_Init (+0x1cacec),
MApi_GOP_InitByGOP (+0x1cb140), MultiAlpha/MIUSel/SetGOPDst.

A static native helper can also issue the same kernel calls directly.
Reconstructed layouts/constants are in mi-display-abi.h:
  /dev/mik!disp: ioctl 0xc00c1200, direct 12-byte DISP init argument
  /dev/mik!osd:  ioctl 0xc00c1400, direct 12-byte OSD init argument
  /dev/mik!sys:  GET_ATTR 0xc0101805, SET_ATTR 0xc0101806
SYS outer wire layout is {u64 attr=5,u64 user_address}; user_address points
to the 8-byte selector/status struct. ARM32 pointers have zero high word.
Kernel +0x38750 confirms 8 bytes for attr 5; +0x36068..0x3609c and
+0x363c4..0x363ec confirm GET/SET dispatch. Exact libmi3 wrappers independently
construct the envelope and ioctl constants. These /dev names are vendor
library literals; inspect native devtmpfs naming/permissions before use.
The header passed C11 syntax/size checks, not hardware ABI execution tests.

4. THE FRAMEBUFFER GATE THAT AUTO-INIT DOES NOT SATISFY
mik init_module .init.text+0x6cc records selector 40=true, not selector 1.
mstar_FB_GetMiDaemonInitStatus .text+0x4c98..0x4cb0 explicitly constructs
{selector=1,ready=0}, calls MI_SYS_GetAttr(5,&status), then reads byte +4.
mstar_fb_open +0xb38/+0xb40 rejects false readiness with -EINVAL (+0xb88).

Stock midaemon at executable 0x30cc..0x30e0 publishes selector 1=true only
after its init work. The replacement must implement the same semantic
completion: verify DISP/OSD and required output state first, then publish
MI_SYS_SetAttr(5,{selector=1,ready=1}), and read it back. Do not set it just
to make open succeed. MI_SYS_SetAttr updates _stModuleInitTable bits at
+0x26c69c onward; it does not perform hardware initialization for the bit.
Exact libmi3 has additional userspace handling for selector 1; direct ioctl
only reproduces kernel state needed by fbdev, not all daemon behavior.

After genuine init and readiness: load mstar_fbdev_mi if not already loaded,
open /dev/fb0 or actual native fb node, FBIOGET_FSCREENINFO/VSCREENINFO,
mmap using returned smem_len/line_length/bitfields; draw opaque Hello and
perform required unblank/pan. Driver open owns MI OSD surface/layer setup;
an additional application-side MI surface need not be assumed. The exact
FBDEV0 is layer 1, 1280x720, format enum 8, IOMMU=1, DFB_RESERVED=1.
Continue reading fb bitfields: enum 8 alone is not the public pixel ABI.
