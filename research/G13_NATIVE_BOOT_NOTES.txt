Boot fixes found during validation:
  - Early-init's audioserver bind remount did not survive as seen by later
    services. Reapply the suid flag from boot.sh, after the stock mount setup.
    This permits the normal init-to-audioserver security transition.

    waiting ten seconds for media.metrics. Set media.metrics.enabled=0
    before audio processes start; the fresh-client 14-case test then passes.
  - SurfaceFlinger retains a 1280x720 layer stack without WindowManager.
    Use that size; hardware scales it to the 1920x1080 panel. The original
    assumption of a 1920x1080 logical surface cropped the launcher.
  - Successful launcher exit (Power) requests orderly stock-init shutdown;
    unexpected failure still selects Android fallback and reboots.

Why the warm handoff works
-------------------------
The earlier dark screen was Android PowerManager going to sleep, not the
launcher exiting. Waking through Android restored the visible launcher.
Native boot holds a kernel wakelock instead of relying on PowerManager.

Stock audioserver waits for ActivityManager, package lookup and scheduling
services after framework removal. src/audio/standalone-app-state.c supplies
the native-only replacements. Its ARM32 UidInfo return has the same 48-byte
layout on this G13. The shared object MUST have DF_1_GLOBAL: libaudiohal@7.1
is dlopened and otherwise misses the requestPriority override and blocks.
The successful trial used a DT_NEEDED entry in a COPY of audioserver, mounted
over /system/bin/audioserver in RAM. The bind mount must permit suid for the
stock init-to-audioserver SELinux transition. System storage is unchanged.
The global shim and patched audioserver built by the candidate builder are
byte-identical to those used in the successful warm trial.

The native audio bridge now recognizes G13's setStreamVolumeIndex symbol
with audio_devices_t, alongside the older unsigned-int spelling. A fresh
--init-policy probe successfully set media stream 3 to speaker index 30/100.
The app's separate low software gain remains unchanged.

1. Keep the existing Screen UART session capturing; do not open another

   secure=no, current-slot=a, init_boot_a size 0x00800000.
3. Flash ONLY the candidate to init_boot_a, normal reboot. First verify the
   Android fallback boots and adb root works. MBOOT may stop in standby;
   one ordinary Power press was needed after the preceding root flash.
4. Select one-shot mode, then normal reboot:
     python3 tools/native-app/g13-boot.py once
   early.sh replaces entry.rc with android.rc and syncs it BEFORE starting
   our services. The already-parsed native startup runs for this boot only.
   Startup failures after boot.sh runs request an Android reboot. A hang
   before early.sh, missing metadata/config, or early kernel/init failure
   is outside that fallback's coverage; retain bootloader recovery access.
5. Verify visible launcher, audible PCM, real remote navigation, no
   system_server/app_process, stable frame/audio logs, correct init_boot
   partition hash, USB ADB and entry.rc already restored to android.rc.
   The zygote service NAME is reused for our shell, so "zygote running" by
   itself no longer establishes an Android framework process.
6. Only after the native boot passes, enable automatic startup:
     python3 tools/native-app/g13-boot.py persistent
   This command requires native_ready, launcher_ready, a live tvinit and
   absent system_server. Check another normal startup before declaring the
   owner's power-on goal complete. Full mains-off startup, remote standby
   and wake still need separate physical verification.
