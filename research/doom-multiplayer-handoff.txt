What is ready
-------------
Two instances of our Doom build can play private-LAN deathmatch using the
original Chocolate Doom 2.2.1 network protocol over native UDP. No SDL_net,
network GUI, Internet master service, DNS resolver or network worker thread
was added. The host auto-launches when the second player joins.

Configuration is one optional read-only file, /etc/doom-network:
  host
or:
  join 192.168.88.1
The address must be numeric IPv4. UDP port 2342 is fixed. No file means the
ordinary solo game. A launcher/device image must configure the NIC before
running Doom; this code does not change interface addresses or routes.

Both peers should use the same FreeDM IWAD. When networking is configured,
/doom/freedm.wad is preferred, otherwise the existing Freedoom1 paths remain
available. Solo keeps its existing Freedoom1 preference. The original Doom
argument mechanism remains intact; no new Doom CLI flags were introduced.

Source changes
--------------
- Restored seven original network C modules (4,789 lines) plus their missing
  headers from the OFFICIAL chocolate-doom-2.2.1 tag, source commit
  2ddd290b8226e1d1f0c52e344e76150261a8c0c3. Existing net_defs.h matched this
  release byte-for-byte. GPL notices preserved; whitespace normalized.
  Source URL and exact adaptations are in src/third_party/doomgeneric/UPSTREAM.
- Enabled FEATURE_MULTIPLAYER and restored original D_StartNetGame and
  BlockUntilStart paths that doomgeneric had disabled via ORIGCODE.
- Guarded obsolete dummy network globals, zero-initialized connect/settings
  structs, adapted M_BindStringVariable to this tree's M_BindVariable API.
- src/doomtv/native/doomtv_net.c: 165-line native POSIX UDP module plus a
  minimal two-player waiting flow, master/query/dedicated-mode stubs, and
  gameplay telemetry. Datagram size <=1500, address table bounded to64.
  The socket is nonblocking and SOCK_CLOEXEC, so Doom re-exec does not leak
  its bound socket into the next session. Startup waits at most30 seconds
  for the second player. It refuses mismatched WAD directories.
- NETSTATE once per35 game tics records a hash of both players' positions,
  angles, health, ammo and commands. It is not a full world-state checksum.
- tools/doom/build.sh compiles90 objects with networking. Its output may be
  isolated with DOOM_BUILD_ROOT; default remains assets/build/doom/TARGET.
- src/doomtv/build.rs requires NETWORK_FEATURE=chocolate-2.2.1-native-udp-v1
  beside the native library. This prevents ordinary Cargo from silently
  linking an obsolete solo-only library after these source changes.
- tools/doom/check-multiplayer.py runs an ARM64/HVF host and ARM32/TCG
  client over a loopback-only QEMU Ethernet socket link. It freezes each
  executable into its evidence directory before hashing/packaging it,
  injects movement and fire independently on both peers, compares state at
  identical simulated tics, and captures both screens.
- No shared test/run.py, test/check.py, platform, video or decoder source
  was edited by this agent. Parent's current changes are preserved.
