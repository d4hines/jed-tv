Storage reservation
-------------------
The vendor update_engine was running initially. app-storage-g13.rc replaces
it with a disabled, one-shot no-op and runs app-storage-g13.sh at early-init.
The script checks exact identity and partition geometry, stops update_engine
and sets the upgrade partition read-only. Both native and Android entry
templates import this reservation. The Linux block flag does not affect
the bootloader's pre-Linux FCIE access. A normal reboot confirmed stopped
update_engine and the retained read-only flag before any app update.
Vendor fstab_late also names /data/vendor/upgrade; the live PID1 mount table
has no mounted upgrade filesystem after reservation. Root can deliberately
clear this software protection; it is not isolation against hostile root.

Keep the original full upgrade backup. The partition previously held ext4
OTA workspace, and installing app banks repurposes that workspace. Eight
sectors of ext4 metadata below the first MiB differed between the initial
backup and the first app trial. That interval includes the earlier normal
boot before reservation; it is not an isolated app-writer comparison.
The first trial preserved bank 1 and the region after the banks, excluding
the intentionally advanced two-sector boot journal. Later comparisons must
use the post-reservation snapshot, not attribute old ext4 changes to FCIE.

Issues reproduced on the TV
---------------------------
The first signed app transfer completed in 45.756s and the bootloader chose
bank 0 on its third-start MBOOT-input path. Independent full storage readback
matched the signed header and all 10432512 payload bytes. Linux then failed
to start the native launcher. No persistent bootloader prefix was installed
on the strength of this incomplete trial.

1. Newly configured loop devices returned EIO when reading both the upgrade
   block device and a regular image file. A read-only dm-linear slice reads
   the same partition contents and mounts EROFS successfully. The mount
   helper now maps exactly 32767 sectors starting at 2049 + bank*32768,
   relative to upgrade. It never exposes another partition or the journal.
2. This platform rejected the EROFS context= mount override. The packer now
   embeds security.selinux=shell_data_file on every inode using PAX xattrs.
   This needs no host root permission. Do not use the first unlabeled image
   as a release even though its bootloader signature is valid.
3. Android mksh exited on failure from the function called inside a sourced
   file, despite the caller's '. file || fallback'. Source only definitions,
   then call dande_mount_apps with the error handler. A fault-injected dmctl
   failure now reaches the handler and the shell survives.
4. Axiom was absent from APP_BINARIES despite being in Home and g13-apps.
   Restored it to the deployment/packaging list. The test image uses all nine
   live app binaries, including the TV's newer Flight binary, not an older
   local build. Original files remain in live-apps/.
5. The launcher's private namespace used a nonrecursive bind of its chroot
   root. This hid the authenticated /bin and /share submounts, so tvinit
   silently executed the old writable copy. Matching file hashes did not
   detect this because the test image deliberately contained the same apps.
   start-android.sh now uses rbind. The readback tool requires EROFS in the
   actual tvinit mount namespace, in addition to checking file hashes.

The second signed image (version 2, bank 1) has the embedded SELinux labels.
The 60.223-second transfer completed; full raw readback matched header and
payload. Bank 0, the first MiB and the reserved tail were unchanged relative
to the post-reservation snapshot. Software reached READY +19.77s, but the
owner reported only backlight. Both the app frame and a SurfaceFlinger
screenshot contained Home. GOP interrupts were zero and a display-service
restart reproduced MI_OSD register-update timeouts. This is NOT a successful
physical Home test. Keep the candidate RAM-only until the output failure
and the mount-namespace check are resolved.

The old installed loader's control reboot restored visible Home (owner
confirmed) and GOP interrupts. The RAM test helper was missing the stock
panel_pre_init / readKL / panel_post_init sequence: its readKL output said
"Panle is not ready". boot-image-tv.py now retains that sequence before
loading the candidate. This fixes the test setup, not the candidate binary.
The helper also checks for the YMODEM sender before issuing TV commands.

The default host ADB transport also became stale during the failed startup.
A second host server on port 5038 confirmed working root ADB. Reconnecting
the offline default transport restored it; this was not a bootloader or
Ethernet failure. UART stayed interactive throughout.
