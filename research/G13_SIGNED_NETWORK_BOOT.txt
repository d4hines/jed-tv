Network boot implementation
---------------------------
The following describes the previous temporary-only revision. The current
application-update gate retains its signed execution protocol and also opens
Ethernet on the third-start fallback; see the current record above.
Target: this G13 / AU13 / serial 18ACC22D1C47, slot a. The network gate opens
Ethernet at 192.168.77.3:7533 before Lean OS preparation. It uses the update
protocol unchanged: canonical LBOOTUP1 manifest, Ed25519 signature over the
96-byte header, SHA-256 payload digest, and Begin/Data/Seal/Abort datagrams.
There is no unsigned mode, embedded sender key or remotely chosen load address.

The sender supplies a temporary bootloader, not a persistent replacement. A
valid Seal freezes the package; after a bounded final-ACK interval the loader
stops MAC DMA, authenticates again, copies and hashes the executable, then calls
it. Returning resumes native OS startup. No upload or rejection also continues
startup. Every third counted start skips Ethernet and uses MBOOT-prepared
inputs for the same native OS; the following start returns to Lean. This is
not Android fallback and does not change slots. See G13_LEANBOOT_DEFAULT.txt.

The final polling budget is 4,000,000 iterations, chosen to target about three
seconds without traffic. It is not a hardware-clock deadline. The first
installed revision used 20,000,000 and measured 15.721 seconds from WAIT to
OS prep, including those backups; that unnecessarily long wait was corrected.
A UART byte can also
end reception. Network traffic and signatures cannot force the loader to
wait indefinitely, although authenticated development code can itself hang.

From the repository root, on the direct Ethernet connection:

  nix develop .#bootloader -c python3 tools/bootloader/update/try-network.py \
    assets/build/leanboot-network/network-example.bin \
    --key assets/private/network-boot/signing.pem --host 192.168.77.3 --reboot

This checks the G13 serial before issuing a normal ADB reboot. Without
--reboot it waits for a manual startup. The third-start escape has no network
window: let it reach Home and retry on the next start. The sender tolerates
temporary route loss and closed UDP ports while the TV starts. The host's
existing dande-tv NetworkManager profile supplies 192.168.77.1/24.

Replace the example with a flat ARM/AAPCS image, position independent or linked
at 0x40600000, at most 1 MiB. --entry is an aligned offset within that image.
The entry receives r0=0x40301000 and a private 64 KiB stack ending at 0x26360000.
Its context contains LNB1 magic, ABI 1, original tags, FDT/kernel addresses,
signed version/length, caller SCTLR and a diagnostic word. Preserve AAPCS
registers, CPU state and resident RAM if returning. A signature authorizes the
code; it does not prove that code satisfies the return contract.

UART sequence for the returnable Lean-to-C example:
  LEANBOOT GATE
  LEANBOOT choice N1  (or N2)
  LEANBOOT WAIT
  LEANBOOT NET
  NETWORK LEAN
  LEANBOOT OS prep
  LEANBOOT Linux
  DANDE_BOOT ... READY: bootloader=Lean; ...

The v4 container stays inside boot_a's existing 128 KiB kernel prefix. A
3660-byte Lean Stage0 expands the 125008-byte gate from an 83584-byte LZ4 block.
Packed original kernel bytes and metadata end at prefix offset 111389. The
other boot-image bytes are unchanged. MBOOT still supplies early hardware
initialization and the kernel handoff. The boot chain remains unlocked and
replaceable by root; this is not an immutable secure-boot trust anchor.

Code and verification boundaries
--------------------------------
NetworkBoot.lean reuses Update.Server.dispatch with an authentication callback
instead of the persistent install callback. It allows repeated signed versions
at or above its compiled minimum of 1 for development. Persistent installNext
still requires a strictly newer version. The bank updater is not enabled on
physical eMMC; its only hardware trial used two RAM banks as described below.

All protocol, copy, validation and orchestration logic is ordinary Lean-to-C.
HACL* crypto remains behind the centralized MemoryM/HardwareM FFI. The call
bridge adds 14 ARM DSL instructions for the separate stack, cache handoff and
return. No new handwritten assembly file, allocator or writable ELF globals
is added. Full assumptions and RAM ownership: src/bootloader/Unsafe/CONTRACTS.txt.

Local checks cover real ARM crypto and payload execution with MMU on/off,
no-upload return, and six full compressed-gate paths including fallback,
recovery, corrupt metadata, preparation and journal failures. Existing Ethernet
checks (193 packets, six driver cases) and the 103-declaration Lean proof audit
passed. These are finite checks and policy proofs, not an end-to-end proof of
the network driver, signature implementation, machine code or flash durability.
